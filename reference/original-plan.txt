
Project Intake Agent: Creatio Hackathon Plan (Industry Agent)

Tagline: "Project intelligence to pipeline for building-products manufacturers." Persona: projects team at Everline Appliances (a fictional US appliance manufacturer). Submission deadline: Wed Sep 30, 2026. Team of 3, 7 days (Sep 23 to Sep 30).


0. Context
Building-product manufacturers get specified into construction projects years before anything ships. Reps find these projects in feeds such as Dodge, ConstructConnect and tender portals, then type them into the CRM by hand. That takes 20–25 minutes per project. It also creates duplicates (a new phase, a renamed project, or a second source for the same project) and misses the architect or specifier. There is no triage.
The agent works in five steps:

1. It reads each incoming project (bulk Excel, or a single email).
2. It extracts the entities.
3. It matches them against existing Projects and Accounts.
4. It recommends a CRM action and classifies pursuit priority.
5. A human approves anything ambiguous, and the agent then writes standard Creatio records.
Decisions already made

Topic	Decision
Build and demo environment	A new hackathon env, not yet provisioned or registered in clio. LocalDev is reference only.
AI	Creatio AI Studio: a native Creatio.ai Agent with Skills (CopilotAgent / CopilotIntent in CrtCopilot). No external LLM keys.
Target records	Project (the physical construction project, with phases via ParentProject) plus Opportunity (our spec/pursuit deal).
Code and package	A new, neutral package UsrProjectIntakeAgent. The existing client package UsrMieleADProjects on LocalDev is a design reference only. Do not copy, ship or depend on it. It must contain no Miele names, client dealers or real projects.
Plan deliverable	Markdown docs and seed-data CSVs in the AI_Creatio folder (list in §11). Nothing is created in any Creatio env during planning.

What LocalDev taught us (reference findings)

- Standard Project (package Project) has these columns: 
- Name, Type→ProjectType, Status→ProjectStatus (required), ProjectEntryType (required), Owner (required)
- Account, Contact, Opportunity, ParentProject
- StartDate, EndDate, Deadline, PlanIncome, Notes
- Related: ProjectProduct, ProjectFile, ProjectRole, ProjectTag
- There is no standard Project↔Account participant object.
- Standard Opportunity has Account, Contact, Partner (Account), Stage, Amount, Budget, Probability, Source, LeadType, DueDate, Owner and Description. OpportunityContact adds Role (Decision maker / Influencer / Contact person), Influence and IsMainContact.
- Standard Account has: 
- Type→AccountType. It includes Contractor, Distributor and Partner. It has no Developer, Architect or Dealer value.
- AccountCategory (A/B/C/D), AlternativeName, Industry, Parent, City/Country/Address
- Relationship links Account↔Account. Lead holds only one company and one contact, so it cannot carry four stakeholders. A dedicated staging object is justified.
- Creatio's built-in duplicate search exists for Account and Contact only (CrtDeduplication). Project matching has to be done by the agent.
- Data import infrastructure is standard: ImportSession, FileImportTemplate (CrtFileImport). Import templates can be saved.
- AI Studio schemas (CopilotIntent) support ResponseFormatJsonSchema, WorkflowOnly, UsePageContext and Prompt. This means skills can return structured JSON and can run from business processes.

Talking point for the pitch: "The staging object mirrors the Dodge API schema. Swapping in the live feed is a connector, not a redesign."
Design principles

1. Standard first. Every final business record is a standard object. The only custom things are the staging object, one participant (junction) object, a few lookups and a few Project columns.
2. Staging stores raw text. Lookups are resolved at apply time. This way an import never fails on an unknown city or type.
3. The rules decide which records the AI compares; the AI makes the call. An ESQ pre-filter picks the candidate projects and accounts. The LLM decides and explains. Thresholds live in system settings.
4. Human in the loop. Only high-confidence new or exact-duplicate results can be one-click applied. Anything ambiguous goes to Needs review.
5. Configurable scoring. Factors and weights live in a lookup, and dealer tier is the standard AccountCategory. Nothing is hardcoded to one customer.

Lookup	Values

Starting scoring factors (configurable weights): construction value, unit count, project-type fit (for appliances: multifamily, hospitality and senior living score high), stage (Design or CD means the spec window is open and scores high; Under construction scores low), architect known, dealer tier A/B, existing relationship with the developer (won opportunities), and region coverage.


3. Import plan (how intake gets in)
3.1 Bulk path: Excel/CSV into staging

1. Template seed-data/ProjectIntake_Import_Template.xlsx. Its columns mirror a Dodge-style feed: Source, Source Project ID, Project Name, Project Type, Stage, Address, City, State, Country, Est. Construction Value, Units, Bid Date, Start Date, Completion Date, Owner/Developer, Architect, GC/Builder, Dealer, Key Contact, Contact Email, Contact Role, Description.
2. Creatio Data Import wizard (from the Project Intake list, Import data): 
- Target object: UsrProjectIntake. Map every column to the text fields. Source maps to the UsrIntelligenceSource lookup by name.
- Duplicate rule inside import: match on UsrSource + UsrSourceId, then update existing. Re-importing the same feed doesn't create new staging rows.
- Save the mapping as an import template (standard FileImportTemplate) so reimports take one click.
3. Imported rows get UsrStatus = New by default.
4. Trigger processing. Use a list action "Run Intake Agent on new items". It starts process UsrIntakeBatchProcess, which reads all New intakes and runs UsrIntakeProcessOne per record (sub-process, "for each record in collection"). Optionally add a timer every 10 minutes. There is no insert-signal, because a bulk import would start 15 parallel LLM runs at once.
5. Progress is visible in the list: status chips go New → Processing → Needs review / Ready to apply.
Idempotency rules:

- A row that is already Applied is never reprocessed by reimport.
- A row whose status is Failed can be re-run.
- Re-running on Needs review overwrites only the AI fields, never reviewer edits to the matched accounts.
3.2 Single path: email or pasted project sheet (the "wow" moment)

- Option A, primary if mailbox sync works in the hackathon env. A shared mailbox projects@… is synced to Creatio. Process UsrIntakeFromEmail starts on Activity insert (Type=Email, recipient = the intake mailbox, or subject contains [INTAKE]). It creates UsrProjectIntake with Source=Email, UsrRawText=Body and UsrEmailActivity linked, then runs UsrIntakeProcessOne. S1 Extract fills the parsed fields from free text.
- Option B, guaranteed fallback shown in the chat. On the Project Intake list, the user pastes the forwarded email or sheet text into Creatio.ai chat and types "Log this project". The chat skill S4 calls action Create intake from text, which runs the same pipeline, and replies with the match, action, priority and rationale.
- PDF (stretch goal). Attach the PDF to the intake. If the env's Creatio.ai can read attachments, S1 reads the file. Otherwise the demo uses the text-bearing email path. Do not promise PDF OCR on stage until it has been verified on Day 1.
3.3 Future connector (slide only, not built)
The Dodge or ConstructConnect REST API pushes to UsrProjectIntake through standard OData/DataService, with UsrSource=Dodge and UsrSourceId=the Dodge project ID. Field mapping goes in docs/03-import-plan.md. No schema change.
3.4 Seed-data load order (demo baseline)
Load in this order, all through the standard Data import:

2. Contacts
3. Projects (parents first, then phases via ParentProject)
4. UsrProjectParticipant

4. Agent design in Creatio AI Studio
Agent: "Project Intake Agent" (Creatio.ai Agent), with the four skills below.

Skill	Mode	Input	Output (JSON schema via ResponseFormatJsonSchema)
S1 Extract Project Intelligence	Workflow-only	RawText	projectName, projectType, stage, address, city, state, country, constructionValue, units, bidDate, startDate, completionDate, developer, architect, builder, dealer, keyContact{name,email,role}, confidencePerField
S2 Match & Recommend	Workflow-only	intake fields + CandidateProjects JSON (≤10: id, name, city, developer, stage, value, phase/parent, external id) + CandidateAccounts per role (≤5 each: id, name, alternativeName, type, city)	matchedProjectId or null, matchConfidence 0–100, matchType (exact / new-phase / renamed / cross-source / none), matchReason, accountMatches{developer,architect,builder,dealer:{accountId or null, confidence, isNew}}, recommendedAction
S3 Classify Pursuit Priority	Workflow-only	intake fields + active UsrScoringFactor rows + dealer tier + developer history (count of won opportunities)	priority, score 0–100, factorBreakdown[], rationale (≤3 sentences), missingInfo[] (for example "Architect unknown")
S4 Intake Assistant	Chat, UsePageContext	page record / pasted text	Actions: Create intake from text, Run agent on this intake, Apply recommendation, Explain decision. Q&A such as "why is this a duplicate?"

How UsrIntakeProcessOne runs each intake (business process):

1. Set Status=Processing.
2. If the parsed fields are empty and RawText exists, call S1 and write the parsed fields.
3. Candidate pre-filter (Read data / ESQ, deterministic): 
- Projects where City = intake city, OR Name contains the first significant token of the project name, OR developer Account Name/AlternativeName contains the developer token, OR UsrExternalId = SourceId. Limit 10.
- Accounts per role: Name or AlternativeName contains the first significant token. Limit 5.
- Serialize the candidates to JSON. Use a script task only if the process designer can't build the text.
4. Call S2, then S3. Map the JSON outputs to intake fields (use a script task to parse if the output-parameter mapping isn't enough).
5. Guardrails (deterministic, from system settings):
- confidence ≥ 85 and action in {Duplicate – no action, Update existing project}: Status = Ready to apply
- Create new project with every account resolved or new, and confidence of "no match" ≥ 85: Status = Ready to apply
- Any 50–84 match, Link as new phase, renamed, or any account match below 85: Status = Needs review
- Required fields missing: Priority = Data incomplete, Status = Needs review
- Error: Status = Failed, with UsrAgentError
Apply flow UsrIntakeApply (from the "Apply" button on the intake page, and only if Status ∈ {Ready to apply, Needs review with the reviewer set}):

1. Resolve or create Accounts. Set Type, and add the raw name to AlternativeName if it differs (this is how the system learns aliases).
2. Act on the recommended action: 
- Create new: create a Project, resolving Type, City and Stage lookups by name, with Owner = current user, Status = Planned and ProjectEntryType = default.
- Link as new phase: create a Project with ParentProject = the matched project.
- Update existing: update Deadline, value, stage and notes on the matched project.
- Duplicate: nothing; link the intake to the project.
3. Upsert UsrProjectParticipant rows for each resolved stakeholder.
4. Create an Opportunity when priority is Strategic or Active and there's no open opportunity on that project: 
- Account = Developer, Partner = Dealer, Budget = the share of construction value we can realistically target.
- Set Project.Opportunity.
- Add an OpportunityContact for the key contact, with Role = Influencer for an architect.
5. For each missing stakeholder, create an Activity task "Identify architect/specifier for ", due in 3 days.
6. Set the intake to Status = Applied, with CreatedProject and CreatedOpportunity filled in. Write the AI rationale into Project.Notes.
Prompt assets. Stored in docs/04-agent-design.md and pasted into AI Studio: system prompt, few-shot examples (one per match type), JSON schemas and scoring rubric.

9. Demo script (≤ 6 min)

1. Pain (30 s). 20–25 minutes per project, duplicates, the architect gets missed, no triage.
2. Bulk (2 min). Import the Dodge-style Excel file, then Run Intake Agent. The list fills with verdicts. Open: 
- Row 4: a duplicate that the agent caught.
- Row 7: a Phase 2 linked to its parent, with the reviewer approving it.
- Row 1: the $180M Strategic tower. Apply, and show the Project, buying centre, Opportunity with the dealer as Partner, and the architect as Influencer.
3. Wow (1.5 min). Forward the architect email (or paste it into chat). In under a minute you get an intake with extracted fields, a Strategic classification, a "Dealer missing" flag, and on Apply a task for the rep.
4. Configurable (30 s). Change a scoring weight, re-run, and the priority changes. "Your dealer tiers are just AccountCategory."
5. Impact (30 s). Dashboard: hours saved, duplicates prevented, architect coverage. "Staging mirrors the Dodge API: connector, not redesign."


10. Risks and fallbacks

Risk	Fallback

LLM latency or quota	Batch runs in the background with status chips. Pre-record a backup video. Merge S2 and S3 into one call if needed
